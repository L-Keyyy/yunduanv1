# 前端界面架构与可视化方案

基于 Vue 3 + TypeScript + Element Plus 构建，采用后台管理系统标准布局 (左侧菜单栏 + 顶部面包屑/用户栏 + 主体内容区)。

## 1. 路由与页面结构 (Pages)

- `/login` : 登录页面
- `/` (Layout):
  - `/dashboard` (首页数据大盘):
    - 顶部：四个核心数据卡片 (当日订单量、昨日同比、待发货订单数、库存告警SKU数)。
    - 中部：ECharts 销量折线图 (近30天趋势) 和 订单状态分布饼图。
    - 底部：最新待处理订单快速入口和系统公告。
  - `/products` (商品与库存管理):
    - 表格视图：展示商品主图、名称、SKU、FBO库存、FBS库存。
    - 操作列：编辑库存按钮、查看抓取/清洗的历史数据分析面板。
  - `/orders` (订单监控):
    - 分页签展示：`FBO 订单` / `FBS 订单`。
    - FBS重点列：倒计时发货时间预警 (Element Plus Tag 组件，临近超时标红)。
  - `/system`:
    - `/system/users`: 用户及权限管理 (RBAC)。
    - `/system/settings`: Ozon API Key 配置中心。
    - `/system/logs`: 系统操作审计日志表格。

## 2. 状态管理 (Pinia)
- `useUserStore`: 管理用户登录状态、JWT Token、角色权限 (用于路由守卫和按钮级权限控制)。
- `useOzonStore`: 缓存从后端拉取的店铺配置字典。

## 3. 实时更新机制
- **WebSocket (Socket.io)**: 建立长连接。当后端 Celery 定时任务拉取到新的 Ozon 订单，或者发现有库存不足的商品时，主动向前端推送通知 (Notification 弹窗提示)。
- **轮询降级**: 若 WebSocket 断开，自动降级为每 30 秒请求一次 `/dashboard/summary`。

## 4. 预留数据清洗与抓取模块集成入口
- 在商品详情页中，增加一个 **“竞品与抓取分析”** 抽屉组件 (Drawer)。
- 当用户点击时，前端通过后端代理调用已有的“抓取模块”数据，展示该商品的市场价格走势和清洗后的结构化数据。
